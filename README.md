# 🌾 Agricultural Chatbot

A floating chatbot widget for farmers: answers questions about maize, rice,
cassava, and tomato using **semantic search** (sentence-transformers), with
an optional free **Gemini API** fallback, plus a simple **buyer/seller**
marketplace backed by SQLite.

Works fully **offline** once the model is downloaded once — no API key
required for the core Q&A feature.

---

## 📁 Folder structure

```
agri-chatbot/
├── app.py              # FastAPI backend: /chat, /sell, /buy
├── train.py             # Run once to build embeddings.pkl from data.json
├── data.json             # 100 Q&A question variations (25 answers) — editable
├── embeddings.pkl        # Generated by train.py (not committed, created locally)
├── agrichatbot.db        # SQLite database (created automatically on first run)
├── index.html             # Demo page showing the widget embedded
├── style.css               # Widget styles (green agriculture theme)
├── script.js                # Widget logic (chat + buy + sell flows)
├── requirements.txt           # Python dependencies
└── README.md                    # This file
```

## ⚙️ How the "brain" works

1. `data.json` holds 25 answers, each with 4 different ways a Nigerian
   farmer might ask the same question (including Pidgin English).
2. `train.py` converts every question into a 384-number "embedding" using
   the **`all-MiniLM-L6-v2`** sentence-transformers model, and saves them
   to `embeddings.pkl`.
3. `app.py` loads that file at startup. When a farmer asks something in
   `/chat`, it embeds their message the same way and compares it to every
   stored question using **cosine similarity** — this means it understands
   *meaning*, not just matching words, so "How I go plant maize" matches
   "When is the best time to plant maize?".
4. If the best match's similarity is **below 0.5**, the dataset probably
   doesn't cover that question well, so the app tries the free **Gemini
   API** (if you've set `GEMINI_API_KEY`). If that's unavailable too, it
   replies honestly instead of guessing.

## 🚀 Running it locally

### 1. Install Python dependencies

```bash
cd agri-chatbot
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Generate the embeddings (first time, and after editing data.json)

```bash
python train.py
```

This downloads the `all-MiniLM-L6-v2` model the first time (~90MB, needs
internet). After that, it's cached locally and runs offline.

### 3. (Optional) Enable the Gemini fallback

Get a free key at https://aistudio.google.com/apikey, then:

```bash
export GEMINI_API_KEY="your-key-here"      # Mac/Linux
setx GEMINI_API_KEY "your-key-here"        # Windows (restart terminal after)
```

Skip this step if you just want the offline dataset-only mode — the app
works fine without it.

### 4. Start the backend

```bash
uvicorn app:app --reload
```

The API is now running at `http://127.0.0.1:8000`. You can check it's
alive by visiting that URL in a browser — you should see a small JSON
status message.

### 5. Open the demo page

Just open `index.html` in your browser (double-click it, or use an
extension like VS Code's "Live Server"). Click the green leaf button in
the bottom-right corner to try it.

> **Note:** opening `index.html` directly as a `file://` page works fine
> for this demo since the widget calls the API by full URL. If your real
> site is served over HTTPS, make sure your backend is too (see below).

## 🧩 Embedding on a PHP (or any) website

Copy `style.css` and `script.js` to your PHP project (e.g. into an
`/assets/` folder), then add these **2 lines** just before `</body>` on
any page you want the widget to appear on:

```html
<link rel="stylesheet" href="/assets/style.css">
<script src="/assets/script.js"></script>
```

By default the widget talks to `http://127.0.0.1:8000`. For a real
deployment, point it at your live backend by setting a config variable
**before** the script tag:

```html
<script>window.AGRI_CHATBOT_API = "https://api.yourfarmsite.com";</script>
<link rel="stylesheet" href="/assets/style.css">
<script src="/assets/script.js"></script>
```

That's it — no PHP-side code needed, since the widget builds its own
HTML with JavaScript and talks to the FastAPI backend directly over the
network. Just make sure your backend is deployed somewhere reachable
(e.g. a VPS, Render, Railway, etc.) and that CORS is allowed (it already
is, in `app.py`).

## 🔌 API reference

### `POST /chat`
```json
// Request
{ "message": "when should I plant maize" }

// Response
{
  "reply": "In most parts of Nigeria, maize is best planted...",
  "source": "dataset",     // "dataset" | "gemini" | "fallback"
  "similarity": 0.87,
  "category": "maize"
}
```

### `POST /sell`
```json
// Request
{
  "product_name": "Maize",
  "quantity": "20 bags",
  "location": "Kano",
  "price": "25000 per bag",
  "phone": "08012345678"
}

// Response: the saved record, including its new "id"
```

### `GET /buy?product=maize`
```json
// Response: array of matching seller records
[
  {
    "id": 1,
    "product_name": "Maize",
    "quantity": "20 bags",
    "location": "Kano",
    "price": "25000 per bag",
    "phone": "08012345678",
    "created_at": "2026-09-14T10:00:00"
  }
]
```

## ✏️ Adding more Q&A

Open `data.json` and add a new object to the list:

```json
{
  "category": "maize",
  "questions": [
    "How do I store harvested maize?",
    "Best way to keep maize after harvest",
    "Maize storage tips",
    "How I go take store my maize?"
  ],
  "answer": "Dry maize to about 13% moisture before storage..."
}
```

Then re-run `python train.py` to rebuild the embeddings, and restart the
backend.

## 🛠 Troubleshooting

- **"embeddings.pkl not found"** → run `python train.py` before starting
  `uvicorn`.
- **Widget shows "couldn't reach the server"** → make sure `uvicorn` is
  running and that `AGRI_CHATBOT_API` points to the right URL.
- **Gemini fallback never triggers / always says fallback message** →
  check that `GEMINI_API_KEY` is set in the same terminal session you
  started `uvicorn` from.
- **First `train.py` run is slow / needs internet** → that's expected,
  it's downloading the model once. Later runs use the local cache.
